# 각자의 AI로 작업하는 방법

세 명이 서로 다른 AI를 써도 결과물이 한 프로그램으로 합쳐지도록, **AI에게 주는 규칙과 자료를 똑같이** 맞추는 문서입니다.
규칙 원본은 저장소 맨 위의 `AGENTS.md`입니다. 이 문서는 사람이 AI에게 무엇을 어떻게 말할지 정리한 것입니다.

## 0. 전체 순서

1. 통합 담당이 이 베이스를 GitHub 저장소에 올리고 두 사람을 초대합니다 (`docs/GIT-GUIDE.md`).
2. 각자 clone → `test.bat`이 통과하는지 먼저 확인합니다. (베이스는 52개 테스트 통과 상태)
3. 자기 페이지 문서(`docs/pages/A-search.md` 등)를 **사람이 먼저** 읽고, 할 기능 순서를 정합니다.
4. 아래 1번에서 내 AI 종류를 확인하고, 2번 "첫 메시지"를 보냅니다.
5. 기능 하나씩: 3번 템플릿으로 요청 → 4번 체크리스트로 확인 → 커밋 → `ai-log.md`에 한 줄 기록.
6. 공용 코드가 바뀌어야 하면 6번 요청서를 통합 담당에게 보냅니다. 직접 고치지 않습니다.
7. 기능이 끝날 때마다 7번 질문으로 내 코드를 설명할 수 있게 만듭니다. (코드 이해도 15점, 교수님 질문 대비)

## 1. 내 AI는 어떤 종류인가

| 종류 | 예 | 준비 |
| --- | --- | --- |
| **저장소를 직접 읽고 고치는 AI** | Claude Code, Cursor, GitHub Copilot(에이전트 모드), OpenAI Codex, Gemini CLI, Windsurf | 프로젝트 폴더를 열기만 하면 `AGENTS.md`(Claude는 `CLAUDE.md`, Gemini는 `GEMINI.md`, Copilot은 `.github/copilot-instructions.md`)를 읽습니다. 2번 첫 메시지만 보내면 됩니다. |
| **채팅형 AI** (파일을 못 읽음) | ChatGPT, Gemini, Claude 웹, 뤼튼 등 | `context.bat A` (B, C)를 실행 → 생긴 `context-pack-A.md`를 채팅에 **첨부** → 2번 첫 메시지. 공용 코드가 바뀌거나 내 코드가 많이 바뀌면 다시 만들어 새 대화에 첨부합니다. |

채팅형 AI가 준 코드는 사람이 파일에 붙여 넣습니다. AI에게 항상 **파일 전체**를 달라고 해야 붙여 넣기 실수가 없습니다.

## 2. 첫 메시지 (복사해서 쓰기)

### A 담당

```text
나는 Java Swing 항공권 예매 팀 프로젝트의 A 담당이야. 내 페이지는 "항공권 검색"(SearchPage)과
"항공권(시간대) 선택"(FlightSelectPage)이고, 수정할 수 있는 곳은 src/airline/ui/page/search/ 폴더와
test/airline/SearchTest.java 뿐이야.

AGENTS.md의 규칙, docs/ARCHITECTURE.md의 페이지 계약, docs/pages/A-search.md의 기능 목록을 먼저 읽어 줘.
(채팅이면: 첨부한 context-pack-A.md에 전부 들어 있어)

읽고 나서 코드는 아직 쓰지 말고 다음만 답해 줘.
1) 내 두 페이지가 세션에서 무엇을 읽고, 다음 페이지로 가기 전에 무엇을 저장해야 하는지
2) 기능 목록 A1~A19를 어떤 순서로 만들면 좋을지와 그 이유
3) 내 폴더 안에 새로 만들면 좋을 클래스 (예: 달력 컴포넌트) 와 각 클래스의 책임
```

(채팅이면: 첨부한 context-pack-B.md에 전부 들어 있어)

읽고 나서 코드는 아직 쓰지 말고 다음만 답해 줘.
1) 내 두 페이지가 세션에서 무엇을 읽고, 다음 페이지로 가기 전에 무엇을 저장해야 하는지 (왕복·유아 포함)

## 3. 기능 하나 요청하기

```text
docs/pages/A-search.md의 A4(달력으로 날짜 선택)를 만들어 줘.

조건:
- 지금 SearchPage의 가는 날 콤보박스를 달력으로 바꾼다. 내 폴더 안에 달력 클래스를 따로 만든다.
- 고를 수 있는 날짜는 searchService.getFirstSearchableDate() ~ getLastSearchableDate()
- 날짜 계산(그 달의 첫 요일, 일수 등)은 화면과 분리한 클래스로 만들고 SearchTest에 테스트를 추가한다.
- AGENTS.md 규칙대로 Java 17 + Swing만, 공용 파일은 수정하지 않는다.

답변 형식: 바꾸거나 새로 만든 파일마다 경로와 파일 전체 코드, 그다음 바꾼 이유와 사용한 OOP 개념 3~5줄.
```

다른 예:
- B: `B11~B13(좌석 배치도, 승객 고르고 좌석 클릭)을 만들어 줘. 좌석 버튼은 JButton을 상속한 클래스로 만들고, 좌석 선택 규칙은 bookingService.checkSeat()로만 검사해.`
- C: `C1~C3(결제 수단 선택, 카드·계좌 입력 폼)을 만들어 줘. 수단마다 폼 클래스를 만들고 같은 인터페이스(createPayment())를 구현하게 해. 형식 검사는 CreditCardPayment/BankTransferPayment 생성자에 맡겨.`

**한 번에 여러 기능을 요청하지 않습니다.** 하나 만들고 확인하고 커밋한 뒤 다음으로 갑니다.

## 4. 받은 코드 확인 체크리스트

- [ ] 바뀐 파일이 전부 내 담당 폴더(+내 테스트 파일) 안에 있다 (`git status`)
- [ ] `test.bat` → `[통과] 모든 테스트를 통과했습니다.`
- [ ] `page.bat 내페이지 ROUNDTRIP`, `page.bat 내페이지 INTL`로 열어서 직접 눌러 봤다 (유아·왕복 포함)
- [ ] 다음 버튼을 누르면 콘솔에 `[세션 검사] … : 통과`가 찍힌다
- [ ] `run.bat`으로 로그인부터 내 페이지까지 이어진다
- [ ] 외부 라이브러리 import가 없다 (`java.`, `javax.`, `airline.`만)
- [ ] 화면 문구에 "항공편"이 없다 ("항공권"으로 통일)
- [ ] 코드를 한 줄씩 읽고, 모르는 부분은 7번 질문으로 물어봤다

## 5. 오류가 났을 때

```text
방금 만든 코드로 test.bat(또는 page.bat SEAT ROUNDTRIP)을 실행했더니 아래 오류가 났어.
원인을 먼저 설명하고, 고친 파일 전체를 다시 줘. 내 담당 폴더 밖은 고치지 마.

[콘솔 내용을 그대로 붙여 넣기]
```

자주 나오는 원인:
- `PageSmokeTest`의 `INTL` / `INTL_ROUNDTRIP`만 실패 → 유아(좌석 없음)나 여권 칸 처리를 빠뜨림
- `ROUNDTRIP`만 실패 → 오는 편(`SegmentType.INBOUND`)을 처리하지 않음
- `HeadlessException` → `onShow()`나 생성자에서 알림창을 띄움
- "화면을 그리기만 했는데 다른 페이지로 이동함" → `onShow()` 안에서 `navigate()`를 부름
- `[세션 검사] … 막힘` → 다음 페이지로 가기 전에 세션에 저장할 값을 빠뜨림 (ARCHITECTURE.md 4절 표 확인)

## 6. 공용 코드 변경이 필요할 때

AI가 "공용 파일을 이렇게 바꾸자"고 하면 **그대로 고치지 말고** 아래 요청서를 쓰게 해서 통합 담당에게 보냅니다.

```text
공용 코드는 내가 고칠 수 없어. 통합 담당에게 보낼 "공용 코드 변경 요청서"를 아래 형식으로 써 줘.

[공용 코드 변경 요청] 담당: B
- 바꿀 파일:
- 추가/변경할 메서드 (시그니처):
- 필요한 이유 (어떤 기능 번호 때문인지):
- 다른 페이지에 주는 영향:
- 공용 코드 없이 내 폴더 안에서 해결할 방법이 있는지:
```

통합 담당은 요청을 GitHub 이슈(라벨 `공용변경`)로 남기고, 반영 후 모두에게 `git pull`을 알립니다.
대부분은 "내 폴더 안에서 해결할 방법"으로 충분합니다. 공용 코드는 세 사람 모두에게 영향을 주므로 신중하게 바꿉니다.

## 8. AI 활용 기록 (`docs/ai-log.md`)

공지 기준으로 사용 도구, 활용 수준(0~4단계), 주요 활용 내용, 팀이 검토·수정한 부분, 팀이 직접 결정한 설계를 남겨야 합니다.
기능 하나를 커밋할 때마다 한 줄씩 바로 적습니다. 발표 직전에 기억으로 쓰면 빠지는 게 많습니다.

```text
| 2026-11-20 | B | ChatGPT | 3 | B11~B13 좌석 배치도·선택 구현 | 좌석 버튼 색 규칙을 직접 수정, 비상구 안내 문구 보완 |
```

커밋 메시지에도 AI 사용을 짧게 남기면 GitHub 이력과 기록이 서로 맞습니다. 예) `[B] 좌석 배치도 추가 (AI: ChatGPT 3단계)`

## 9. 하지 말 것

- "프로그램 전체를 만들어 줘", "베이스를 더 좋게 다시 짜 줘" → 세 사람 코드가 서로 안 맞게 됩니다.
- 공용 파일(`domain`, `service`, `payment`, `ui` 바로 아래 등) 직접 수정
- 다른 담당 폴더 수정, 다른 담당 페이지 클래스 import
- 외부 라이브러리 추가 (JCalendar, FlatLaf 등), 빌드 도구 변경 (Gradle/Maven 전환 등은 팀 합의 후 통합 담당만)
- AI가 준 코드를 실행·이해하지 않고 커밋
- 실제 카드번호·계좌번호를 테스트에 쓰기 (테스트 번호 `4111 1111 1111 1111`만 사용)
